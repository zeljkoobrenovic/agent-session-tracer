One column per API call (a turn); the agent's tools in that turn below the token bars. The top rows show what each turn costs: the context re-sent from the prompt cache, the new context written to it (tool results, the agent's own words) and the output. The file rows show where the agent read, searched and edited. Drop a trace JSON here to render it. Make one from any Claude Code session with python3 turn_trace.py --cwd /path/you/ran/claude/in --out trace.json (--list shows the sessions of a folder); see the repository.

Reading the bars: the blue bar grows every turn because the whole conversation so far is re-sent with each call, and the thin slice on top of it is what the turn added, which the next turn re-sends in blue; the second row shows that slice alone: the results of the tools it called last turn (orange, estimated at 2.3 characters per token, the rate measured on these transcripts), the agent's own previous words and tool calls (green), on the first turn the session setup (yellow: the session-specific system prompt sections, the skill and agent listings, CLAUDE.md, the task prompt) and later the per-turn reminders and instructions the CLI injects (grey). The light-blue base of every blue bar is the static prefix shared by all sessions, the fixed system prompt and the tool definitions, which the CLI keeps cached, so even the first call reads it rather than writing it. The cost of a session is mostly the area under the blue bars, so the number of turns and what each one appends matter more than any single read. Lines attributed to files are those in tool output: a Read or cat/sed/head of the file counts as read lines, an Edit as edited lines, a grep output line naming the file as a search hit.
